# 免费运行诊断演练

从 Agent 的「Trace 与错误诊断」或全栈的「可观测性」课进入 Playground「运行诊断」。四种固定场景调用现有只读课程工具，不需要模型密钥。

## 先看证据，再判断

1. 选择场景，点击「运行诊断演练」。每次显式运行获得新的服务端运行 ID。
2. 查看搜索、读取、摘要三个阶段的状态、实际耗时与工具 dispatch 次数；未执行的阶段没有模拟耗时。
3. 填写终态、停止阶段和 dispatch 次数，点击「核对我的判断」。答案取自本次实际报告。
4. 对失败案例，可点击「切换到正常场景」，再手动运行，比较两次报告。切换按钮不会发起请求。
5. 填写「我的观察与下一步」，核对后预览，再明确追加到本课笔记。错误判断也可以记录反思。

固定目录正常时，可用以下结果检查自己的理解。目录或工具结果变化时，应以实际报告为准，不能从场景名称直接推断结果。

| 场景         | 实际行为                                                | 预期终态 / 停止阶段  | dispatch |
| ------------ | ------------------------------------------------------- | -------------------- | -------- |
| 正常         | 搜索课程、读取首个命中、整理已读标题与摘要              | success / summary    | 2        |
| 没有证据     | 真实搜索固定不匹配词，得到空数组                        | no_evidence / search | 1        |
| 参数拒绝     | 把固定错误类型交给工具，schema 拒绝                     | rejected / search    | 1        |
| 本地等待超时 | 搜索后、读取工具调用前，用 25ms 时限取消 200ms 本地等待 | timed_out / read     | 1        |

`dispatch` 表示已把请求交给工具，不代表工具成功。空搜索没有工具错误，根阶段 `passed` 也不代表找到证据。超时例的读取阶段已经进入，但 `lesson_read` 没有调用。

## 报告包含什么

`POST /api/playground/diagnostics` 只接收 `track`、`lesson_id`、`scenario`；课时必须是正确路线中唯一的 `agent-tracing` 或 `fullstack-observability`。不接受任意查询、工具、代码、URL 或超时参数。

报告采用 `run-diagnostics-v1`，包含运行 UUID、路线/课时/场景、终态、停止阶段、工具次数和固定三个子阶段。每个子阶段通过父 ID 关联根阶段；时间来自服务端 monotonic 时钟，顺序不重叠，时长为实际起止差。未执行阶段的时间为 `null`。

公开证据只来自本次真实课程工具：搜索命中的 ID、实际读取的课时标题/摘要/来源，以及据此拼接的固定摘要。摘要不调用模型。`cleanup_completed` 只说明本次局部编排的 `finally` 已运行；`timeout_wait_cancelled` 记录本地等待实际收到取消。

接口拒绝额外字段、重复 JSON key、非法 UTF-8、非有限数、过深或超过 4096 字节的请求；固定 422 不回显输入。既有平台 50000 字节上限也可能更早返回 413。内部异常或不合法工具证据返回固定 500，不返回部分报告；报告最多 32768 字节，本接口响应均 `no-store`。正常业务中的拒绝或超时返回 HTTP 200，应读取报告终态判断结果。

## 保存与重新运行

判断修改后需要重新核对；观察修改后需要重新预览。保存读取最新本课笔记，追加本次实际报告、个人判断和原文观察，并用完整运行 ID 防止重复。每篇笔记最多 10000 字符，全部笔记最多 1000 篇；容量不足保留草稿。浏览器存储失败时明确提示仅在内存保留，可导出备份救援。

切换场景、课时、路线、Playground 模式或离开页面会使旧请求失效；导入或清空学习记录也会丢弃旧报告。客户端停止等待不证明服务端已收到取消。迟到响应不能回填新的场景或重置后的记录。

演练不写模型运行历史，不自动完成课时、标记语言实践或创建证据卡。个人笔记仍使用原 v1 备份格式。

## 边界与验证

这是固定的本地编排练习，覆盖工具参数、无证据、阶段计时、局部取消和记录判断；不诊断真实供应商、网络或数据库故障，也不提供生产 tracing、远程资源释放或通用语义正确性证明。模型、沙箱、数据库和外部命令调用均为零。

后端行为测试在 `tests/test_run_diagnostics.py`，协议与笔记测试在 `tests/run-diagnostics*.test.ts`，真实页面到 API 的流程在 `tests/test_run_diagnostics_browser.py`。执行证据见[验证记录](verification.md)；具体版本的 CI、Preview、内置 Browser 与 Production 分别记录。
