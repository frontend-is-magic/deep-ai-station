# 流式用量与失败结果

Playground 在流进行中显示供应商已经返回的计数。实验失败、达到输出上限或手动停止后，这些值继续留在当前结果区，缺失部分保持未知；只有完整成功的回答可写入运行历史或本课笔记。

## 协议

API 的 `usage` 事件包含 `run_id`、`usage`、`usage_complete`。`usage` 只含已知的 `prompt_tokens` / `completion_tokens` / `total_tokens` 整数；完全未知为 `null`，真实零值保留为 `0`。单请求各字段上限 100,000,000，最多三轮的累计字段上限 300,000,000。

事件是该次运行的累计快照，前端替换当前快照，不累加事件。供应商同一请求更新某字段时替换旧值，未出现的字段不补零；Agent 按各轮最新快照汇总，收到最终 `done` 不再加一次。`error` 也附最后快照，旧协议未提供新事件的成功结果和历史记录继续兼容。

| 状态                         | 展示与完整性                                    | 历史和笔记           |
| ---------------------------- | ----------------------------------------------- | -------------------- |
| 运行中                       | 已知计数或未知；`usage_complete=false`          | 不保存               |
| 正常成功                     | 所有实际开始请求正常结束且三字段均已知时为 true | 保存成功结果         |
| 后轮配额拒绝                 | 未发出该轮模型请求，已完成前轮的计数可完整      | 保留失败状态，不保存 |
| 供应商错误、超时或缺失终止帧 | 保留已收到计数，标记不完整                      | 不保存               |
| 达到模型输出上限             | 回答未完成；计数完整性独立判断                  | 不保存               |
| 用户停止或网络中断           | 仅保留浏览器已接收快照，保守标记不完整          | 不保存               |

运行失败不代表供应商没有计费；完整计数也不等于最终账单。平台不推算缺失值或金额，且不会将用量快照写入共享请求配额表。当前失败结果仅在页面内存保留，刷新或开始新实验后清除；集中用量账本与跨设备同步仍待实现。

## 取消与隔离

后端在读取到合法 usage 帧时立即提供快照，无需等待整个 Agent 成功。Agent 的运行级 tracker 与 API 共用，后续错误响应仍可取到早前已知计数。每轮在获准开始后才加入 tracker；未获准的后轮不会制造一次未知模型调用。

取消或关闭生成器时只清理连接，不尝试强行发送最后一帧。浏览器收到停止信号后保留快照并标记不完整，不等待服务端补发。回调核对当前请求身份并拒绝终态之后的事件，旧请求不能覆盖新实验；失败后迟到的 `done` 也不会写成功历史。

`usage_complete=true` 仅描述本次已开始请求的计数字段及正常结束证据。它不表示回答正确、课程通过、供应商账单结算或取消后没有费用。

## 验证与来源

单元与 mock 测试检查早到用量、重复/更新快照、部分字段、真实零值、异常脱敏、逐轮配额拒绝与连接关闭。headless 测试检查显示、停止、失败历史、旧协议恢复与移动布局。另有浏览器 → 独立本地 HTTP API → 实际供应商解析器的集成测试，远程供应商使用 MockTransport，配额准入使用固定回调，验证后轮错误和真实 HTTP 断开后的上游关闭。该链路不验证 PostgreSQL 配额，数据库行为由独立 CI 任务检查。所有服务器仅绑定自有回环端口，结束后释放。

[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 说明最终内容块携带请求用量，随后以 `[DONE]` 终止；实现同时接受 OpenAI 兼容的独立 usage 块。测试覆盖这两种形状，不能替代真实 DeepSeek、Vercel Python 断连行为或原生 Browser 验收。执行结果按提交记录在 [验证记录](verification.md)。
