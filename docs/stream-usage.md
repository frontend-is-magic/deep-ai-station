# 流式用量与失败结果

Playground 在流进行中显示供应商已经返回的计数。实验失败、达到输出上限或手动停止后，这些值继续留在当前结果区，缺失部分保持未知；已结束的成功、失败和客户端停止记录都进入最近 20 条本地历史；只有完整成功的回答可写入本课笔记。

## 协议

API 的 `usage` 事件包含 `run_id`、`usage`、`usage_complete`。`usage` 只含已知的 `prompt_tokens` / `completion_tokens` / `total_tokens` 整数；完全未知为 `null`，真实零值保留为 `0`。单请求各字段上限 100,000,000，最多三轮的累计字段上限 300,000,000。

事件是该次运行的累计快照，前端替换当前快照，不累加事件。供应商同一请求更新某字段时替换旧值，未出现的字段不补零；Agent 按各轮最新快照汇总，收到最终 `done` 不再加一次。`error` 也附最后快照，旧协议未提供新事件的成功结果和历史记录继续兼容。省略 usage_complete 保持未知，不改成明确的 false；客户端停止、断流和缺失终止帧仍强制标记不完整。

| 状态                 | 展示与完整性                                    | 历史和笔记                                    |
| -------------------- | ----------------------------------------------- | --------------------------------------------- |
| 运行中               | 已知计数或未知；`usage_complete=false`          | 不持续落盘                                    |
| 正常成功             | 所有实际开始请求正常结束且三字段均已知时为 true | 保存 completed；可写笔记                      |
| 后轮配额拒绝         | 未发出该轮模型请求，已完成前轮的计数可完整      | 保存 failed / server_error                    |
| 供应商错误、超时     | 保留终态最后快照，完整性与回答成败分开          | 保存 failed / server_error                    |
| 达到模型输出上限     | 回答未完成；计数完整性独立判断                  | 保存 failed / output_limit                    |
| 缺失终止帧、网络异常 | 仅保留已收到快照，标记不完整                    | 保存 failed / stream_ended 或 transport_error |
| 用户停止、同应用切页 | 客户端停止等待；已接收计数标记不完整            | 保存 cancelled / user_stop 或 context_changed |

运行失败不代表供应商没有计费；完整计数也不等于最终账单。平台不推算缺失值或金额，且不会将用量快照写入共享请求配额表。服务端[模型请求账本](model-usage.md)独立保存逐轮计数与状态，不保存回答，也不提供跨设备学习记录同步。

## 本地终态记录

每次尝试开始即建立本地 UUID，作为历史 `id`；`server_run_id` 只保存实际收到的有效服务端运行 ID，开始前的 HTTP 拒绝或立即停止不会假造服务器运行。课时、路线、供应商和任务在开始时固定，切到另一课后结束的旧请求不能归入新课。

成功、失败、截断和客户端取消使用同一个终结入口，最多保存一次。记录仅包含白名单中的任务、已接收回答、最多 12 项轨迹、已知用量、终态和固定原因；不复制访问码、系统提示全文、请求头、原始错误对象或诊断正文。用户自行输入的内容也属于本地记录，所有终态共用最近 20 条上限。存储失败时沿用内存保留与导出提示，不能据此声称已写入磁盘。

回看只恢复显示，失败片段标明未完成，停止时仍在运行的轨迹展示静态观察状态。旧 v1 记录没有 status 时仍按原成功记录兼容；失败和取消不能写入本课笔记，任何记录都不会自动确认课程通过。历史回看不会重试模型或代码执行，只有明确点击运行才建立新尝试。运行中直接硬刷新、关页或浏览器崩溃尚不支持恢复；已结束的记录可以刷新后回看。

导入和清空更新 `history_reset_id`，使此前活动尝试失效并丢弃其未结束片段；旧流即使忽略取消，也不能把清空前内容写回。合法旧备份可读，导入时建立新标记；非法备份不改变现有记录。终结写入前读取最新进度，保留新笔记与其他字段；localStorage 跨标签写入仍是最后写入者生效，不宣称事务合并。导入上限仍为 2,000,000 字节，完整导出超过该值时会明确提示不能直接导回。

## 取消与隔离

后端在读取到合法 usage 帧时立即提供快照，无需等待整个 Agent 成功。Agent 的运行级 tracker 与 API 共用，后续错误响应仍可取到早前已知计数。每轮在获准开始后才加入 tracker；未获准的后轮不会制造一次未知模型调用。

取消或关闭生成器时清理连接，并有界尝试记录取消终态，不尝试强行发送最后一帧。浏览器收到停止信号后保留快照并标记不完整，不等待服务端补发。回调核对当前请求身份并拒绝终态之后的事件，旧请求不能覆盖新实验；失败后迟到的 `done` 也不会将原失败升级成成功。

`usage_complete=true` 仅描述本次已开始请求的计数字段及正常结束证据。它不表示回答正确、课程通过、供应商账单结算或取消后没有费用。

## 验证与来源

单元与 mock 测试检查早到用量、重复/更新快照、部分字段、真实零值、异常脱敏、逐轮配额拒绝与连接关闭。headless 测试检查显示、停止、失败历史、旧协议恢复与移动布局。另有浏览器 → 独立本地 HTTP API → 实际供应商解析器的集成测试，远程供应商使用 MockTransport，配额准入使用固定回调，验证后轮错误和真实 HTTP 断开后的上游关闭。这组浏览器测试使用替身账本；另有真实 HTTP API → PostgreSQL → 同一供应商解析器的集成测试，确认逐轮原子准入、持久化故障与断连。数据库竞争、升级和跨进程行为由独立 CI 任务检查。所有服务器仅绑定自有回环端口，结束后释放。

[DeepSeek Chat Completions 文档](https://api-docs.deepseek.com/api/create-chat-completion/) 说明最终内容块携带请求用量，随后以 `[DONE]` 终止；实现同时接受 OpenAI 兼容的独立 usage 块。测试覆盖这两种形状，不能替代真实 DeepSeek、Vercel Python 断连行为或原生 Browser 验收。执行结果按提交记录在 [验证记录](verification.md)。
