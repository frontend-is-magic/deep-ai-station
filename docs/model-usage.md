# 模型请求账本

每次真实 DeepSeek 请求先在 PostgreSQL 同一事务内扣除共享请求配额、插入一条获准记录，再向供应商发送请求。Agent 的一至三轮分别记录；教学演示、免费检索与工具契约实验不产生账本。模型仍使用 OpenAI 兼容的输入输出，密钥只在服务端。

## 记录与未知值

`public.ai_model_usage_v1` 的主键是 `(scope, run_id, request_index)`。它只保存 UUID、轮次、供应商和模型名、三项 token 计数、快照序列、状态、有限原因枚举与数据库时间，不保存 prompt、回答、代码、工具参数、用户身份、访问码、连接串或原始异常。

| 状态        | 含义                                                                |
| ----------- | ------------------------------------------------------------------- |
| `admitted`  | 已确认准入；仍在执行或终态未确认，不能当作零消耗或成功              |
| `completed` | 供应商正常终止且流/自有客户端清理完成；回答正确性与任务成功另行判断 |
| `failed`    | 上游、超时或账本故障已记录；已获准配额不返还                        |
| `cancelled` | 取消清理时已确认记录终态；不保证供应商立即停止或没有后续费用        |

`prompt_tokens`、`completion_tokens`、`total_tokens` 缺失时为 `NULL`，已知零为 `0`。供应商解析器先更新同轮已知字段，再以最新累计快照替换账本旧值；重复帧不相加，缺失字段不补零；不从输入和输出推算总量。单字段上限 100,000,000。`usage_complete=true` 要求正常完成且三字段均有效；`truncated` 单独表示输出上限，不能用计数完整推断回答完整。

快照序列单调递增；旧序列不覆盖新值，同序列冲突拒绝。终态不可变，相同终态重复提交不增加计数，冲突终态拒绝。进程重启不清空数据库；进程退出、断连或提交确认丢失后可能留下 `admitted` 行，后续汇总继续显式显示。当前没有自动重试、后台补账或供应商账单对账。

## 事务与故障

模型配额和获准行在短事务中一起提交。主键冲突、额度耗尽、缺少迁移或写入错误均不允许发起本次上游请求；提交结果不明时保守拒绝，不重试、不退回内存，也不再扣一次额度。事务结束后才等待模型网络，详情见[共享配额](shared-quota.md)。沙箱配额不写模型用量表。

收到用量后先更新运行内存快照，再尝试持久化。数据库写入失败停止当前流及后续模型轮次；错误 SSE 仍保留内存中已知值，但不宣称它已持久化。正常 `done` 只有在读取结束、自有响应与客户端关闭、终态提交成功后发送。终态提交结果不明不尝试改写成失败。

取消或关闭生成器保持原始取消信号，不在清理阶段发送 SSE。关闭供应商资源与取消账本写入在同一任务中做有界清理，不遗留脱离请求的后台写入；数据库不可达或清理超时可能使最后记录仍为 `admitted`。真实托管网络、Vercel Python 断连传播及供应商计费须另行验收。

## 迁移与权限

沿用服务端 `AI_QUOTA_MODE` / `AI_QUOTA_DATABASE_URL` / `AI_QUOTA_SCOPE`，不增加客户端配置。连接串只通过托管 secrets 注入维护进程，不放在命令参数、聊天、文档或仓库。程序不会自动加载 `.env`。

```sh
uv sync --locked
uv run python scripts/setup_quota.py
```

维护脚本在同一事务依次执行仓库固定 `001_request_quota.sql` 和 `002_model_usage.sql`，已有配额和账本均保留；运行请求不执行 DDL。先用有建表权限的维护角色迁移，再给应用角色两张表的 `SELECT / INSERT / UPDATE` 权限。升级已存在的配额库时必须执行新迁移，否则真实模型请求固定返回 `503`，免费功能继续可用。Preview 与 Production 分别配置稳定 scope 或数据库，不轮换 scope 绕过额度。

本地明确选择 `memory` 时可验证同进程协议，重启清空，不提供持久化或跨进程保护；生产禁止。日报 CLI 只接受 PostgreSQL，不会把新进程的空内存当作历史。

## 只读 UTC 日汇总

```sh
uv run python scripts/report_model_usage.py --date 2026-10-04
```

命令仅按当前配置的 scope 查询 `[当天 00:00 UTC, 次日 00:00 UTC)` 的 `admitted_at`，不使用本机时区，不修改记录。输出 JSON 包含总尝试数、四种状态计数、三字段的已知值之和、各字段未知请求数，以及完整/不完整请求数。`known_usage` 在该字段所有请求均未知或当天无请求时为 `null`，真实零保留；有部分未知时求和仍只是已知小计。不同模型合计不换算价格，不提供金额或额度重置。

报告角色可仅获账本表的 `SELECT` 权限；命令不输出原始运行 ID 或内容。配置、连接或 SQL 错误只返回固定诊断和非零退出码。报告文件可能包含内部运营数据，若需保存，应写入已忽略的本地目录，避免误提交。

## 验证边界

单元测试验证内存/数据库共同状态语义、序列、终态及固定脚本。独立 PostgreSQL 17 测试检查双进程竞争、同主键准入、两处事务故障回滚、提交确认丢失、锁超时和取消、001 升级、无 DDL 应用角色、UTC 边界、NULL/0 与真实日报 CLI。另有真实回环 HTTP API → PostgreSQL → 实际 DeepSeek SSE 解析器的测试，供应商使用 MockTransport，验证一至三轮、写入故障停止后续请求、失败保留早前用量及断连释放。

真实 PG 测试只读取专用 `TEST_QUOTA_DATABASE_URL`；缺失明确 skip，已配置后连接/SQL 失败必须失败。测试会创建临时表、随机测试数据库与角色，并删除自身 scope；只允许一次性测试集群，禁止生产地址。CI 使用独立临时服务。实际通过数与版本见[验证记录](verification.md)；这些测试不代表托管数据库、真实 DeepSeek、原生 Browser 或 Production 已通过。
